# C 同一渡船的米制几何合同 v1.2

状态：开发版几何与规则已核验；不是最终美术验收。该合同关闭旧合同第 8 节的“D01 放大后艇型变宽”问题。冻结的 r3 发布包与其 v1.1 合同保持原样；本版用于下一批 C 开发和美术 blockout。正文 v1.1 / 大纲 v0.5 不改，战斗、船油、灯油、配重算法不改。

权威入口：`current-geometry.json`。构造数据来自 `tower-campaigns/src/campaigns/c/content.js#VOYAGE_VESSEL_GEOMETRY`，六张真实地图来自同一文件。所有下述尺寸是项目设计值，不冒充原文给出的尺度，也不是实船制造规格。

## 1. 可直接交给美术/3D 的最小包

1. `vessel-hull-v1.2.obj`：同一艘船的低模封闭实体，10 顶点 / 16 三角面；单位米，绝对不能分别拉宽、压短
2. `vessel-physical-geometry-v1.2.json`：同 mesh 顶点、各设备安装点、槽位、货架、人物安全位、连续部件及规则身份
3. `map-space-contract-v1.2.json`：五张泊位 + D01 的真实通行层和设备层
4. `world-schematic-v1.2.json`：原港区总览不动，增加同一船体到当前泊位的刚体变换
5. 本文和 `qa/map-correspondence-validation-v1.2.json`：允许/禁止事项与真实可达性证据

旧 `map-space-contract.json` 和旧正文合同保留用于 r3 历史，不得让美术工人把两个版本的甲板掩码混用。背景/CG 的旧 packet 如仍引用旧文件，制作时以本版五项覆盖船体、D01 掩码、吊臂手柄和剑的可见性；世界建筑、人物正典及原文不被覆盖。

## 2. 一个物理船体，不以网格外形冒充船型

右手坐标：X 向右舷，Y 向上，Z 向船尾；船首是负 Z。船长 6m、最大宽 3m，长宽比 2:1。甲板面 Y=0.8m、水面 Y=0，底面 Y=-0.5m。

顶视轮廓按 XZ：`(0,-3), (1.5,-2.4), (1.5,3), (-1.5,3), (-1.5,-2.4)`。这是短收尖船首、长直工作舷、平艉的同一小型港内工作船。底圈略收，见 JSON/OBJ。这个母体在五泊位、D01、GAL 和后续 3D 只实例化/平移/旋转，不复制成五个不同船。

### D01 格到船体

- `X = 0.6 × (x - 5)`
- `Y = 0.8`
- `Z = 0.6 × y - 2.7`

x/y 两方向都恰是 0.6m，严禁不同缩放系数。船首尖在 D01 连续坐标 `(5,-0.5)`，船尾在 `y=9.5`，最大舷缘在 `x=2.5 / 7.5`，完整艇体落在 11×11 的连续外边界 `[-0.5,10.5]` 内。它无需撑满 11 列；两侧留水就是正确画面。

### 船体到泊位图

- `berthX = 5 + X`
- `berthY = 5.5 + Z`
- 合并：`berth = (2 + 0.6x, 2.8 + 0.6y)`

泊位格距 1m。完整船体包络仍是 `(3.5,2.5) 到 (6.5,8.5)`，恰落原来 x4..6、y3..8 的 3×6 保守占位里。D01 工作面变为 5×9 个采样位置，既不拿旧 7×9 矩形当船体，也不把 5×9 当整个船壳的尺寸。

### 船体到世界

先转换到当前泊位局部坐标，再使用既有 `schematic = origin + R(yaw) × (scale × berth)`。船体采用 X右舷/Y上/Z船尾，世界采用 X东/Y上/Z南，两套都是右手坐标。返回 `[schematicEast, scale×physicalY, schematicSouth]`；船首负Z，不能把 Z船首 的反手基与此混用。转换线性部分行列式为 `+scale³`，已测试 yaw=0/180/53 三种角度。scale=4 是统一总览单位换算，不是单独拉伸船体。C-M04 的 yaw=180 是刚体旋转，不能镜像右舷。D01 用 `boat.dock` 所指泊位的同一姿态，仅更换相机。

## 3. D01 真实导航和设备层

可站格是 x3..7、y1..9，扣除三个永久设备格 `(3,3)/(5,3)/(7,3)`，共 42 格。全部连通；x4/x6 两条操作通道仍连接船首和船尾。

三个设备格分别是左/中/右货架的固定定位区。即使灯座已移走或卸岸，该处仍有固定滑道/机座，不开放“穿过货架”的路径。货架沿横向浅埋滑道移动；两条人行通道的轨道应做齐平处理，不画成横跨走道的绊脚高梁。移动不是第三套实时物理系统。

导航人物半径设计为 0.18m；每条正交可走边的扫掠路径都已校验在艇体内，且不穿过任何货架箱体包络。这里的尺度只约束布局。人物身高不因格子变化而变、也不参与配重运算。

六槽仍是 L1(3,4)、L2(3,6)、C1(5,4)、C2(5,6)、R1(7,4)、R2(7,6)。原文 c03 是浅铁槽及盖板：使用嵌入甲板的低槽和齐平盖面，操作结束的可走状态不能画成挡路高箱；保留实际铁块/空槽状态和唯一 ID。三枚质量 1/1/2 的铁块不得复制。

物理横向力臂为左 -1.2m、中 0、右 +1.2m，正好是现规则归一化力臂 -1/0/+1 的统一倍数。货架左/右也是 ±1.2m，灯座质量 2，对应原 ±2 的归一化力矩；数值玩法没有改动。

## 5. 边缘交互、安全位与唯一上岸点

- 吊臂机身显示锚保留 (8,3)；新实际操作热点 (8,2) 也不可站。两者为同一连续设备，固定支脚在真实船体内。唯一操作位 (7,2)，与右货架 (7,3) 纵向相隔0.6m；箱体投影 + 人物半径仍有净空。收臂与吊装用同一操作位
- 不再从 (7,3) 站到灯座箱下操作。c16 纱雾在吊臂手轮前侧，璃在 (6,5) 牵导向绳，澜音站岸端接货区侧面，不站在 (8,5) 箱体落点正下方
- M03 绞盘机身/手柄/操作者分别 (5,3)/(4,3)/(4,4)，观察人 (4,2)。牵引缆经船首导缆器走船首右侧，不能经过观察人与操作者脚下；两个站位均不在承重缆及其延长线上
- 船上双主缆从右舷导缆器向外到桩，不横穿六槽/走道。靠泊动作热点 (7,9) 表达两缆依口令依次系妥的原子作业；不能把同格小信号灯画成系缆执行器
- D01 到岸热点仍 (8,7)，不可站，从 (7,7) 唯一操作。其物理映射分别为泊位 (6.8,7)/(6.2,7)，都属于同一跳板通道。泊位粗格 (6,7) 是同通道船端的交互采样，不要求不同分辨率格心严格重合
- 登船仍落 D01 (7,7)，离甲板仍回当前泊位 (7,7)。没有免费跨泊位、外海出口或新增步桥

## 6. 统一镜头与二维回退

母体和设备坐标固定，地图正交镜头只做等比例 zoom 与平移。D01 仍完整显示11×11工作图与船首轮廓，不把水面留白填成更宽船舷。高吊臂/近侧栏杆可透明/cutaway，但不能移位或改变逻辑通路。

3D、GAL、2D 母版都用同 geometryId。2D 回退读同一地图和真实状态，实体位置不因预渲染图被迫移动。GAL 可裁切、不镜像；需看到配重时必须显示当前实际布局，不能锁死样例解。对话安全区不应遮住设备连接、唯一跳板或关键配重来掩饰不一致。

本版 OBJ 只是可验证的几何 blockout。尚未批准任何 C 环境像素或最终船体材质，仍须进行无人背景/实际镜头的艺术 QA。
