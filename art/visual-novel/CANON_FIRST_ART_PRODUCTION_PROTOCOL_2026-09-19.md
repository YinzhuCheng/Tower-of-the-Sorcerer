# Canon-First 美术生产事故复盘与强制操作规范 · 2026-09-19

## 0. 文档目的

本文记录 2026-09-19 GAL 对话立绘生产中的一次身份一致性失误，并将后续角色立绘、表情差分与剧情 CG 的生产顺序固化为强制规范。

适用范围：

- GAL 对话立绘 / 表情差分
- GAL 对话头像
- 剧情 CG
- 战斗 CG
- 角色相关宣传图 / 审核图
- 任何会重新表现已建立角色身份的图像资产

本规范不改变魔塔玩法层已有地图、敌人、机关、物品资产的保留策略。

---

## 1. 本次失误

### 1.1 发生了什么

在 B2「25 个实际调用的对话立绘 / 表情差分」启动时，先生成了 10 张候选立绘。生成提示中虽然写入了角色的文字 hard locks，例如：

- 绫星·璃：月牙发夹、左肩月牙扣、两枚腰扣、左腰记录包、右手剑、左侧剑鞘；
- 无声女王·诺克缇娅：三主尖峰王冠、中央红菱、喉部红菱、三枚封印片、无剑；
- 残响精灵·纱雾：左鬓五瓣白花、两条背腰飘带、完整银圆环星盘；

但生成时**没有先将仓库中已经验收的三视图、细节板、表情板、中性立绘作为实际图像参考输入**。

因此得到的图像虽然满足部分文字饰品描述，但在以下身份维度发生明显漂移：

- 脸型
- 五官比例
- 刘海与发型轮廓
- 发量与发束结构
- 肩颈与体型比例
- 服装裁片结构
- 袖型、裙摆和装饰密度
- 已验收 CG 中建立的人物视觉身份

### 1.2 结论

本批 10 张仅视为实验 / 失败候选：

- **不计入 B2 完成量**
- **不得进入 accepted manifest**
- **不得替换 public 运行时文件**
- **不得作为后续 CG 的身份参考**
- **不得推送为正式角色资产**

如需保留，应只进入 rejected / experiments 类目录并明确标注失败原因。

---

## 2. 根因

### 2.1 将“文字 hard locks”错误等同于“视觉身份锚”

文字描述可以锁定可枚举属性，例如：

- 发饰数量
- 左右归属
- 道具数量
- 武器所在手
- 主色
- 是否有某个配件

但文字描述不能可靠锁定：

- 具体脸型
- 眼距与眉眼比例
- 鼻口位置
- 发型剪影
- 身材比例
- 衣服的真实裁片结构
- 角色在系列中的整体视觉气质

因此：

> 文字 hard locks 是约束，不是身份母版。

### 2.2 生产顺序错误

错误顺序：

```text
文字描述
  ↓
直接 text-to-image 生成表情立绘
  ↓
尝试用生成结果继续做角色差分
```

正确顺序：

```text
角色文字设定
+ 三视图
+ 细节板
+ 表情板
+ 已验收中性立绘
        ↓
统一角色 Canon
        ↓
基于 Canon 的中性立绘 / 对话立绘
        ↓
从同一母立绘编辑出表情 / 姿态差分
        ↓
将最终立绘加入 CG reference chain
        ↓
CG R2 → R3 → R4
```

### 2.3 CG 与立绘之间缺少同源参考

现有 19 张新版 CG 已完成：

- R0 构图 19/19
- R1 身份 19/19

这些 CG 不需要推倒重做。

问题在于 B2 立绘启动时，没有强制要求它与 CG R1 使用同一套 Canon 图像参考链，因此出现“CG 中的人”和“新生成立绘中的人”不是同一个人的视觉效果。

## 4. 图像参考优先级

生成任何角色新图时，图像参考优先级固定如下。

### P0：三视图

作用：

- 锁脸
- 锁发型
- 锁头身
- 锁服装轮廓
- 锁主色
- 锁正侧背结构

三视图是角色身份的最高视觉优先级。

### P1：细节板

作用：

- 锁饰品
- 锁左右归属
- 锁扣件数量
- 锁武器 / 道具结构
- 锁鞋、腰包、冠饰等局部

### P2：中性立绘

作用：

- 锁 GAL 画面中的成年感
- 锁视觉小说常用比例
- 锁站姿、服装落体和角色气质
- 作为表情差分编辑母版

### P3：表情板

作用：

- 锁眼型
- 锁眉形
- 锁嘴型
- 锁角色允许的情绪幅度

### P4：文字设定

作用：

- 补充不可见约束
- 进行数量校验
- 明确左右
- 明确禁用项

文字不得覆盖 P0–P3 已建立的视觉身份，除非 Canon 文件本身明确修订。

## 5. B2 对话立绘 / 表情差分生产规范

### 5.1 禁止做法

禁止：

- 每个表情从零 text-to-image
- 只引用文字 hard locks
- 用旧 runtime 低清头像代替 Canon
- 为“增强细节”擅自增加饰品
- 改变发型长度
- 改变年龄感
- 改变身材比例
- 改变服装裁片
- 改变角色主色
- 改变武器种类

### 5.2 正确做法

对每个角色：

```text
Canon 三视图
+ Detail
+ Neutral Standee
+ Expression Board
+ 文字 hard locks
        ↓
身份 QA
        ↓
确定一个对话立绘母版
        ↓
image edit
        ├─ neutral
        ├─ guarded
        ├─ resolve
        ├─ sorrow
        ├─ knowing
        └─ ...
```

表情差分默认只允许改变：

- 眉
- 眼
- 嘴
- 视线
- 头部轻微角度
- 手势
- 小幅上半身姿态
- 合理衣摆变化

默认不得改变：

- 脸型
- 发型
- 发饰
- 衣服结构
- 武器
- 道具
- 身高感
- 胸肩比例
- 腰臀比例
- 鞋
- 主色

## 6. CG 的正确衔接

现有新版 CG 状态：

```text
R0 layout    19/19
R1 identity  19/19
R2           0/19
R3           0/19
R4           0/19
```

B2 立绘完成后，CG 不重新回到 R0。

正确路径：

```text
当前 CG R1
+ 对应最终 Standee
+ 角色 Turnaround
+ Detail
+ Environment Canon
        ↓
R2 服装 / 物件精确修正
        ↓
R3 场景 / 叙事修正
        ↓
R4 最终稿
```

### R2 禁止事项

R2 只修：

- 配件数量
- 左右手
- 武器和道具
- 服装结构
- 发饰
- 角色与物件归属

R2 **不得重新设计脸和发型**。

### R3

检查：

- 时间
- 天气
- 光向
- 场景结构
- 固定物件数量
- 对话框安全区
- 角色空间位置

### R4

检查：

- 手指
- 四肢
- 脸部
- 边缘
- 伪文字
- 水印
- 重复物件
- 串角
- 统一线条
- 色彩
- 噪声
- 景深
- 灯光

## 7. 生成前强制检查清单

任何角色图像生成前必须确认：

- [ ] 已读取角色 md
- [ ] 已加载 turnaround
- [ ] 已加载 detail
- [ ] 已加载 neutral standee
- [ ] 已加载 expression board
- [ ] 已确认 hard locks
- [ ] 已确认左右方向以“角色本人”为准
- [ ] 已确认禁止物件
- [ ] 已确认当前生成阶段
- [ ] 已确认目标只允许修改的维度

只要缺一项，不得开始正式生产。

## 9. 版本管理规范

### Canon

Canon 只存：

- 已通过的角色定义
- 已通过三视图
- 已通过 Detail
- 已通过 Expression
- 已通过 Neutral Standee

### Working

工作稿进入：

```text
art/visual-novel/04_cg/working/
```

或对应 standee working 目录。

### Rejected

失败生成必须保留明确阶段和原因：

```text
rejected/
  identity-drift/
  accessory-error/
  anatomy-error/
  style-drift/
```

不得覆盖成功母版。

## 10. 分支规范

正式生产基线始终以：

```text
main
```

的最新 Canon 为准。

临时导出、工具性 workflow 可以存在于临时分支，但：

- 不得修改 main 的 Canon
- 不得在临时分支建立新的角色身份
- 临时分支只负责传输 / 导出 / 检查
- 正式资产只有在 QA 完成后才合并 main

当前一次性 Canon 导出分支：

```text
tmp/canon-art-export-20260919
```

只用于将远端二进制 Canon 资源可靠落盘到生产 VM。

## 12. 核心原则

> **角色身份必须来自同一个视觉 Canon。**

> **文字是约束，三视图 / Detail / Standee 才是视觉身份锚。**

> **表情差分优先编辑同一母立绘，不独立重新设计角色。**

> **CG 精修只允许修正当前阶段目标，不得借精修之名重新换脸。**

> **任何未经过 Canon reference chain 的角色图，不得进入正式资产。**
