# Coupled F5 forgiveness + F6-F8 pressure compensation

## Why this stage exists

The first failure-core repair search found a real constraint conflict:

```text
V2 baseline: 6/58 catastrophic, margin 14.95%
F5-only repair: 3/58 catastrophic, margin 66.72%
```

The repair works for robustness but destroys difficulty. Therefore V3 cannot be generated by one global scalar or by softening the failure enemies alone.

This stage explicitly separates the two time domains:

```text
F5 and earlier: forgiveness repair
F6-F8:         pressure compensation
```

The repository-selected forgiveness seed is provenance data, not production balance:

```text
flameCaster.def 70 -> 44
dragonBoss.atk  114 -> 111
```

It was selected automatically as the lowest-relative-edit first-pass repair; it remains locally blocked because its pressure margin is 66.72%.

## Compensation search

`searchV2CoupledRepairCompensation()` reconstructs the V2 semantic witness, applies the persisted repair seed and reruns purchase 1-opt. It then constructs a compensation catalogue restricted to:

- enemy hazard parameters only;
- floors 6, 7 or 8;
- fields `hp`, `atk`, `def`, `magicPower`;
- no gold/supply edits;
- no F5 edits.

The strict floor split prevents the compensation generator from directly undoing the failure-core repair. This is a generation constraint, not a proof that rescued mistakes remain viable: every fully evaluated compensation candidate reruns all 58 counterfactuals and exact later-purchase recovery.

## Monotone fixed-witness boundary

For each late hazard field, the tuner searches a single-parameter hardening ray on the repaired purchase-1opt witness.

For a fixed event skeleton, raising enemy HP/ATK/DEF/magicPower is monotone with respect to legality: a harder value cannot make an already failed battle legal. The tuner therefore:

1. binary-searches the largest hardening value for which the repaired witness still authoritatively replays;
2. checks whether the minimum normalized HP margin can reach the upper pressure target (25%) before that replay cliff;
3. when reachable, binary-searches the **smallest hardening** whose fixed-witness margin is at or below 25%.

This produces a compact frontier instead of brute-forcing every integer value of every late enemy stat.

## Adaptive-player recheck

The fixed-witness boundary is only a cheap seed. The player may change later purchases once the late game becomes harder. Therefore Top-K boundaries receive:

1. purchase 1-opt under the combined V2 + F5 repair + late compensation overlay;
2. all 58 single-purchase counterfactuals;
3. exact fixed-event-order later-purchase recovery.

The coupled local gate requires:

- purchase local optimum;
- pressure margin inside `[0.08, 0.25]` after purchase adaptation;
- catastrophic mutations <= 4/58;
- no improving single-purchase neighbor;
- zero unknown recovery cases.

Any passing result remains dry-run. It must be persisted as a V3 semantic reference and then checked by the stronger whole-game event-order threshold and staged c6->c7->terminal searches.

## Current scope limit

Version 0.1 searches **single late compensation fields**. If no single F6-F8 hazard can restore pressure without destroying robustness, the next extension is a distributed two-/three-lever compensation ray. The code should not respond by widening the pressure band or weakening the catastrophic gate.
