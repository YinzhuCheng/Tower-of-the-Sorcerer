# 第二章美术与叙事管线

本项目把“可编辑的高清美术”和“浏览器实际加载的素材”分开，避免为了 Git 历史或首屏体积把游戏内肖像压得不可读。

## 两层素材

| 层级 | 内容 | 保存位置 | 规则 |
| --- | --- | --- | --- |
| 母版 | 1024px 以上的 PNG/WebP、分层源文件、生成提示词与角色设定 | GitHub Release 附件或 Git LFS 的私有 `art-source` 仓库 | 不进站点构建，不进入普通提交历史 |
| 运行版 | 256×384 WebP 肖像、58px 格子的透明精灵、少量图标 | `public/assets/anime/` | 普通 Git 与 Vercel CDN；单张应尽量低于 80 KB |

高清母版应以一个版本化压缩包发布，例如 `art-source-v1.zip`。GitHub Release 附件不会让正常克隆或 Vercel 构建下载母版；如果需要持续协作编辑，则将母版放在独立的 LFS 仓库。不要把它们编码进 JSON/Base64：Base64 会额外增加约三分之一体积，并让缓存与差异审查变差。

## 运行时约定

- `src/game/anime-portraits.js` 只为对话、图鉴、HUD 读取 `characters/*-runtime.webp`。
- 地图棋盘仍只读取有透明通道的精灵图，不能拿带背景的全身肖像替换 58px 小格图。
- 新角色应先制作高清母版，再导出两种小图：对话肖像（256×384 或 320×480 WebP）与棋盘精灵（透明、64px 或 128px WebP）。
- 每张运行图用浏览器和 `identify` 核验尺寸、格式与透明通道；不要只根据文件扩展名判断。

## 第二章叙事规则

第十阵结束的是诺克缇娅的黯星封印；第十一阵揭示仍在自动执行的“起源登记”。它最初是灾害期、三日后必须撤销的分配工具，后来被永久化为强制授权。

- 璃反对的不是风险管理，而是不可质问、不可撤销的单方命令。
- 纱雾是共同责任者：她设计过紧急登记，又因恐惧而默许其永久化。
- 回声摄政官把执照视为保护弱者的责任；他的论点必须成立，才能迫使璃给出比“魔法应自由”更完整的回答。
- 奥术主权者把一次灾难中的有效救援误当成永久统治的正当性。终章不销毁记录与安全知识，只销毁自动替人作决定的命令层。

关卡说明可使用单段文本；Boss、人物转折与章节开场使用 2–5 句 `turns` 序列。UI 会逐句显示，避免在战斗前堆出无法阅读的长段落。
