# 20F：冻结拓扑后的分段求解与数值变异

本记录定义第二章（F11–F20）数值收敛的执行顺序。它不是数值表，也不授予自动写生产数值的权限。

## 不可变前提

在任何求解或变异之前，以下内容已由静态拓扑校验和锁快照固定：

- 房间边界、楼梯、卡片/守卫结界与其保护目标；
- Boss 集中节奏、关键单位身份和关键 MP 宝物身份；
- F10 的核心 → 显现上楼梯 → 魔力觉醒转场；
- F5、F15 两个商店的位置与 F15 的 MP 功能。

`src/tuner/demo-20-floor-solver-profile.js` 会捕获这些锚点；任一候选改动地图、门、卡、楼梯、单位身份或宝物身份时，`assertDemoTwentyFloorSolverLocks` 必须拒绝它。允许的只有第二章敌人的数值、MP 恢复/容量数值和 F15 MP 商店效果。

## 为什么分段，而不是从 F1 反复穷举

F1–F10 已有引擎重放的胜利路线。`createDemoTwentyFloorBridge` 会在完整 20F 运行时重新执行那条路线，得到 F10 核心已败、MP=100/100、动态 `U` 已显现的真实压缩状态。它不手工伪造角色属性。

第二章的搜索从这个桥接状态开始。F5 仍是有意义的跨章经济决策，不能粗暴禁用；`demo-20-floor-continuation-adapter.js` 将每一次回访压缩为：

1. 传送到 F5；
2. 购买一项当前可负担的正常升级；
3. 传送回当前第二章楼层。

该宏返回三条原始引擎步骤，所以找到的证书仍可被普通重放器验证。它只折叠已经完成的第一章“走路”，不删除 F5 的购买选择，也不限制 F12 以后回访 F15。

## 迭代算法

1. **静态门禁验收**：先验证结界是割点、保护目标真实、房间可达、Boss/楼梯位于正确门后。失败时回到拓扑设计，禁止数值补丁。
2. **权威桥接**：重放上一阶段证书，生成下一阶段初态；动态阶段变身、楼梯、MP 与卡片均由 `engine.js` 执行。
3. **低预算侦察**：`runDemoTwentyFloorMutationScout` 在相同扩展预算下测量候选的生成边、被支配剪枝、队列峰值和最深到达层。增压候选优先用于压缩明显宽松的普通遭遇；它们不能单凭评分被采纳。
4. **里程碑求解**：`runDemoTwentyFloorMilestones` 依次证明 F15、F18 和最终胜利。某段成功的原始步骤会成为下一段的重放前缀，因此不需要让末段反复发现第一章。
5. **可行性探针与窄化**：若某一守卫群连一条合法战斗边都没有，先用可逆的粗粒度软化探针确认是数值阈值，而不是地图/事件实现错误；随后围绕阈值做更细的数值射线搜索。粗探针永不直接部署。
6. **最终验收**：只对存在完整引擎重放胜利路线的候选做完整预算搜索、回放、截图和手工审查；最终才写入 `DEMO20_NUMERIC_BASELINE`。

## 当前测量结论

在 F10 真实桥接状态、保留 F5 商店宏的前提下，基线的 3,000 状态侦察可到达 F14，但尚未打倒任一三守卫；更高预算的 F14 单守卫里程碑也未出现成功标签。这说明首个必经 Boss 群不是“标准策略失败”，而是当前 bootstrap 数值尚未进入可行窗口。

`f14-guardians-feasibility-soften` 是临时数值档案：它将三守卫降到明显偏软的范围，仅用于验证“F15 是否存在可重放到达路线”。测试已证明该路线存在，且锁快照不变。它不是建议的正式难度；下一步应在这个上界与当前基线之间做窄化，保持 Boss 群的压迫感，同时至少保留一条完整解。

`demo-20-floor-f14-ray.js` 已把这一步做成可回滚的射线扫描：`strength=0` 是基线，`strength=1` 是上述偏软端点；每个样本都运行 F15 里程碑求解并记录是否真正到达、搜索预算、路线长度与到达生命。扫描只报告“已验证可行样本”，不会把预算耗尽误写成不可行，也不会把最软端点写回生产数值。当前手工确认的中间样本表明 50% 仍未进入可行解，而 70% 虽能抵达 F15 但余量极低；因此后续应先建立可接受余量带，再继续向后半章推进。

## 求解器一致性修复

本轮同时修复了两个不能用数值掩盖的运行时问题：

- `tower-codec.js` 现在登记由击败转换 Boss 动态生成的 `U`，所以 F10 的核心格可安全压缩、还原并作为上楼动作搜索；
- `tower-adapter.js` 现在与 `engine.js` 一样枚举任意命名的卡片结界与守卫结界，并按楼层允许的商店选项生成动作。此前它只认识旧 F7 三卡门，会悄悄漏掉第二章正确门禁。

这些修复保证“变异器先筛、求解器后证”的对象始终是同一款游戏。
